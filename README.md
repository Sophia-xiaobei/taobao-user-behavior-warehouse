# 淘宝用户行为离线数仓与分析看板

## 项目简介
基于 Hadoop + Hive + Spark 生态搭建离线数仓，对千万级（约 989 万条）淘宝用户行为数据进行分层建模与清洗，产出大盘指标、转化漏斗、复购率、RFM 用户分层等分析结论，并通过 Pyecharts 可视化看板呈现。

## 技术栈
Hadoop / Hive / Spark SQL / Docker / Pyecharts / Git

## 数仓分层架构
ODS（原始层）→ DWD（明细层）→ DIM/DWS（维度与汇总层）→ ADS（应用层）

## 核心工作
1. Docker Compose 一键部署 Hadoop + Hive + Spark 伪分布式集群
2. ODS→DWD 数据清洗：窗口函数去重、非法值过滤，设计 5 条质量规则
3. 维度建模：用户/商品维度表 + 用户×天、商品×天 DWS 汇总宽表
4. ADS 指标：每日大盘、转化漏斗（浏览→购买转化率 4.5%-5.2%）、复购率 12.48%、RFM 四类用户分层
5. Pyecharts 可视化看板

## 业务结论
1. **转化漏斗**：浏览人数 954,234，加购人数 321,616，购买人数 164,442。加购→购买的转化率高达 51.1%，而浏览→加购的转化率仅为 33.7%，说明主要流失发生在“浏览→加购”环节。建议优化商品详情页和推荐算法，或发放“加购专属优惠券”刺激加购。
2. **复购率**：总购买用户 164,442，其中复购用户 20,525，复购率仅为 12.48%，低于电商行业平均水平（约20%-40%）。建议针对已购用户建立私域运营或推送复购券，提升用户生命周期价值（LTV）。
3. **RFM分层**：一般用户（85,250人）与重要发展用户（79,038人）占比极高（合计约 99.8%），而重要价值用户仅 146 人，重要保持用户仅 8 人。由于数据集仅包含 9 天行为，且缺少真实消费金额，用户整体频次偏低。建议将营销资源向“重要发展用户”倾斜，通过精准触达将其转化为高价值用户。
